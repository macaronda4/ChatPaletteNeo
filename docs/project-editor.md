# Project編集画面

- 左側は幅240のExplorer、中央は本文、右側は話者と操作ボタンです。
- 本文はURL入力欄と同じ幅、話者と各ボタンは「接続」と同じ幅になります。
- Explorerのファイルをクリックすると開き、青い背景と枠で開いているファイルを示します。
- 「前へ」「次へ」はExplorerの上から順のファイルへ移動します。折りたたまれたフォルダ内も対象です。
- 「保存」または `Ctrl + S` で話者と本文を保存します。「送信」は接続先のメインタブへ、編集中の話者と本文を送信します。送信ではファイル保存や次のファイルへの移動は行いません。
- 編集中に他のファイル・Projectへ切り替える場合やアプリを終了する場合は、保存／破棄／キャンセルを確認します。

## 作成と保存

本文と話者の入力欄では、`Ctrl + Z` で元に戻し、`Ctrl + Shift + Z` または `Ctrl + Y` でやり直せます。履歴は入力欄ごとに独立しています。別ファイルを開くと履歴を初期化し、保存では履歴を保持します。元に戻した後に新しく編集すると、やり直し履歴は破棄されます。

`Ctrl + N` でも新規ファイルの名前入力画面を開けます。作成先は開いているファイルと同じフォルダ、ファイル未選択時はProjectルートです。作成後は新しいファイルを開きます。未保存の変更の確認をキャンセルした場合、ファイルは作成しません。

ファイルの右クリックメニューから「送信」を選ぶと、そのファイルを開いて通常の送信処理を行います。別ファイルへ切り替える場合は未保存の変更を確認し、キャンセル時は送信しません。現在開いているファイルを送信する場合は、編集中の話者・本文を使用します。未接続時や送信中はメニューの「送信」が無効になります。

Explorerを右クリックしてファイル／ディレクトリを作成できます。ディレクトリ上ではその中、ファイル上では同じ階層、空白部分ではルートに作成します。右クリックメニューには作成先が表示されます。名前の入力画面ではEnterで作成、Escでキャンセルでき、使用できない名前は画面内に理由を表示します。ファイル名には必要に応じて `.json` を付けます。

新規Projectは、左上の「新規」から開始します。Explorer上部の「Project保存」を押すと保存場所とProject名を選べます。既存Projectでは同じ `.cpn` を上書きします。新規Projectで最初にファイルの「保存」を押した場合も、Projectの保存先を選びます。

本文のJSON形式:

```json
{"speaker": "話者名", "text": "本文\n次の行"}
```

`.cpn` の内容はツリーの配列です。ファイルの保存先は `.cpn` のあるフォルダを基準にExplorerの階層から決定し、`data.path` に相対パスを記録します。

```json
[
  {
    "text": "シーン1",
    "type": "directory",
    "data": {"path": "シーン1"},
    "children": [
      {
        "text": "導入.json",
        "type": "file",
        "data": {"path": "シーン1/導入.json"},
        "children": []
      }
    ]
  }
]
```

この場合、本文は `.cpn` と同じフォルダの `シーン1/導入.json` に保存されます。

保存済みProjectでは新規作成やD&Dのたびに `.cpn` も更新します。D&Dでは実ファイル／ディレクトリも移動します。移動先に同名の項目がある場合は中止し、Project保存に失敗した場合は移動前へ戻します。編集中の本文はD&Dで自動保存せず、編集欄に保持します。

`type` のない旧形式も読み込めます（子あり＝directory、子なし＝file）。空ディレクトリは `"type": "directory"` を明示してください。旧形式に `data.path` があっても、保存先はExplorerの階層を基準とします。既存の本文JSONは上記の相対パスに置いてください。本文ファイルがない場合はエラーを表示し、空の内容で置き換えません。

## バックグラウンド接続

1. URL欄へ `https://ccfolia.com/rooms/ルームID` を入力し、「接続」を押します。
2. 専用スレッドでヘッドレスChromiumを起動し、匿名でルームへ接続します。ブラウザのウィンドウは開きません。
3. 接続中からURL欄をロックします。接続成功後はボタンが「切断」に変わり、ファイルを開いている場合に「送信」が有効になります。
4. 「切断」でブラウザとセッションを終了します。切断完了後、URL欄が編集可能になり、ボタンは「接続」に戻ります。接続失敗時も同様に復帰します。

「ログイン（任意）」ボタンを常に表示します。未接続時は接続失敗の有無にかかわらず利用できます。上部にルームURLを入力し、ボタンからアプリ内のメールアドレス／パスワード入力欄を開いて「ログインして接続」を押してください。別ウィンドウは開きません。通常の「接続」ボタンでは匿名で接続でき、ログインは必須ではありません。接続処理中・接続中はログインボタンを無効化し、切断や接続失敗後に再び有効化します。認証情報はファイルやログへ保存しません。切断後の再接続は匿名から開始します。

SNSログイン・追加認証・CAPTCHAには未対応です。権限のないアカウントは、ログインしてもアクセスできません。普段使いのブラウザのログイン状態は利用しません。

送信先は「メイン」固定です。本文は改行を含めて一括入力します。送信中は連打を防ぎ、自動再送は行いません。入力欄が空になった場合でもサーバーへの到達は保証できないため「送信操作完了（到達未確認）」と表示します。結果不明の場合は、再送する前にココフォリア側のログを確認してください。

接続処理は日本語版のチャット画面に依存します。入力欄・送信ボタンの仕様が変わった場合はエラーになります。実ルームへの投稿・実アカウントでのログインは未検証です。

検証ルームで「メイン」のアクセシブル名が通知数を含む `メイン 0` になることを確認しました。タブ名の完全一致ではなく、タブ一覧内の `button#main[role="tab"]` を指定し、選択後は `aria-selected` の更新を待ちます。候補なし・複数候補の場合は要素数を表示し、先頭タブへの代替送信は行いません。話者欄はラベル「名前」ではなく、実画面で確認した `input[name="name"]` を使います。

入室時の案内が操作を妨げる場合は、「7日間再表示しない」を含む案内ダイアログ内の「閉じる」を押します。チェックボックスは変更せず、ログイン画面や未知のダイアログを自動で閉じません。タブ操作中に案内が遅れて出た場合に限り、閉じてからタブ選択を一度だけ再試行します。メッセージ送信は再試行しません。

通常のルームURLは `/chat` 専用画面のURLへ変換して接続します。最初から `/chat` または `/chat/` の付いたURLも利用でき、`/chat` を重複させません。ユーザー提供の検証ルームで、通常画面と `/chat` のHTML、案内の閉じる操作、`/chat` での情報→メインへの切り替えと選択状態をブラウザで確認しました。ヘッドレスのPythonアプリ全体を実ルームに接続する試験と、実際の投稿は行っていません。自動テストではブラウザをモックしています。

## 実行・検証

Python 3.9以降とTkが必要です。

```sh
python -m pip install -r requirements.txt
python -m playwright install chromium
python main.py
python -m unittest discover -s tests -v
```

GUIテストにはディスプレイが必要です。Linuxでは `xvfb-run -a python -m unittest discover -s tests -v` でも実行できます。ディスプレイのない環境ではGUIテストのみスキップされます。

接続処理のテストはブラウザをモックするため、Chromiumをインストールしなくても実行できます。Linuxで実際に接続する場合、Chromiumのシステム依存ライブラリも必要です（Playwright公式のインストール手順を参照）。
